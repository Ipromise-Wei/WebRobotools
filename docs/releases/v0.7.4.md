# v0.7.4 版本说明

发布日期：2026-09-28

本版修正 Web 显示缓存与工控机实时 SLAM 地图的语义混淆，使手动建图和自动建图的演示可以在不共享旧地图状态的情况下切换。

## 问题原因

旧的“清地图缓存”只清除 Web 后端保存的 OccupancyGrid 和路径副本，不停止、不重置工控机上的 SLAM Toolbox。因此运行中的 SLAM 会很快再次发布 `/map`，给人“地图没有清除”的感受。

现场使用 ROS2 Humble，已在工控机确认其 `slam_toolbox` 安装不提供 `slam_toolbox/srv/Reset`。本版因此不依赖不存在的重置服务，而是使用全新 SLAM 进程建立空白地图。

## 新的建图逻辑

1. 选择“手动建图”或“自动建图”。
2. 如果 Frontier 正在运行，先请求它取消当前探索。
3. 工控机运行代理停止全部 Web 受管 ROS2 进程组，包括旧 SLAM、Nav2 和通信中继。
4. 按选择的方案重新启动模块，新 SLAM Toolbox 进程从空白实时地图开始。
5. Web 后端同步清除旧地图和路径副本，等待新会话的地图数据。

“停止建图”、“全部停止”和单独停止 SLAM 同样会清理 Web 端地图/路径状态。原按钮改名为“清显示缓存”，并在二次确认中明确提示它不会重置正在运行的 SLAM。

## 数据保护与已知边界

- 模式切换清理的是当前内存中的实时 SLAM 地图；未保存的建图成果不可恢复，页面会在操作前二次确认。
- `/home/hzauaiot/.local/share/webrobot/maps` 内已保存的 YAML/PGM 文件不会被自动删除。删除历史地图文件应作为独立、明确的破坏性操作实现。
- 运行方案重启期间机器人模块会短暂离线；浏览器等待上限已调整为 90 秒，不应在第一次点击后反复提交启动指令。
- Web 停止与模式切换不替代物理急停；自动建图必须由现场人员监控。

## 验证

- 工控机实机检查确认 ROS2 Humble 中 `slam_toolbox/srv/Reset` 不存在。
- 后端测试 19 项通过、1 项仅在 ROS2 环境可运行的测试跳过；新测试验证 Frontier 停止请求、整栈停止和新方案启动的执行顺序。
- 前端 TypeScript 类型检查与生产构建通过：`npm --prefix frontend run build`。
