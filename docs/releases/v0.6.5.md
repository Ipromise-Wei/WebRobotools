# v0.6.5 版本说明

发布日期：2026-09-28

这是针对“发送 Nav2 目标后机器人间歇前进、视频明显卡顿”的实时性补丁版本。

## 导航路径与速度心跳

Nav2 在导航中会高频发布 `/plan`，且一条全局路径可能包含大量点。旧 Web 适配器会在 ROS 回调持锁期间将每一条完整路径转换为 Pydantic 对象，再推送给浏览器。这会与导航激活心跳、TF 和里程计回调竞争同一执行资源。若工控机侧看门狗一度收不到新鲜导航心跳，就会按安全策略输出零速度，表现为机器人走走停停；同一后端 CPU 竞争也会延迟 MJPEG 视频转发。

本版仅优化显示链路：

- `/plan` 的 Web 路径最多每 0.5 秒更新一次，每次最多保留 256 个均匀采样点，并保留起点和终点；
- 路径点转换在 ROS 锁外执行，最终替换快照时再短暂加锁；
- ROS2 `MultiThreadedExecutor` 从 2 个执行槽调整为 3 个，导航激活心跳、TF/里程计定时器和地图/路径回调不再轻易互相阻塞；
- Nav2 内部接收的完整全局路径、控制频率、速度平滑、目标安全校验、看门狗超时和物理急停均未改变。

## WebSocket 空闲稳定性

Python 3.10 的 `asyncio.wait_for()` 在超时时抛出 `asyncio.TimeoutError`。地图与机器人 WebSocket 之前捕获了错误的异常类型，因此客户端空闲约 15 秒可能出现 ASGI traceback、断连和重连。本版会将这种预期的空闲状态作为心跳处理。

## 验证与使用

- 已完成 Python 语法编译、补充路径抽样/限频和 WebSocket 空闲心跳回归用例，并通过前端 TypeScript 与生产构建。
- 本机环境未安装 pytest；请在部署服务器的 ROS2 虚拟环境中执行 `cd backend && PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv-ros2/bin/pytest` 获得完整测试结果。
- 更新后重启后端即可生效。导航时应观察到 `/health` 持续快速响应、Uvicorn 不再被单个路径回调长期占满，并且机器人不应因 Web 路径显示而触发看门狗的间歇归零。

若停止 Web 页面或关闭相机后机器人仍以数秒为周期走停，应立即停止导航并在工控机上单独检查 Nav2 `/webrobot/nav_cmd_vel`、速度看门狗输出 `/cmd_vel`、底盘 CAN 和激光/定位负载；这属于 Web 服务之外的真机运行链路。
