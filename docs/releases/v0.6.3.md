# v0.6.3 版本说明

发布日期：2026-09-28

这是 v0.6.2 资源优化后的地图传输性能补丁。

## 问题与原因

`/map` 是大型 OccupancyGrid。旧协议将每一个栅格值作为 JSON 数字发送；一张百万级栅格地图会形成数 MB 至数十 MB 的文本，并在每次 WebSocket 更新时占用 FastAPI 主线程进行 Pydantic 序列化和 JSON 编码。即使地图快照已限速，主线程仍可能接近一个 CPU 核心，继而使 `/health`、认证和控制接口超时。

## 改进

- 栅格数据现在按 ROS `int8` 原始字节打包、以低压缩等级 zlib 压缩并 Base64 传输；未知区域 `-1` 与占据值 `0~100` 保持原样。
- 地图传输负载只包含一次压缩后的字符串、元数据和路径。当前 Chrome 前端使用原生 `DecompressionStream` 解码为 `Int8Array`，避免恢复为耗内存的 JavaScript 数字数组。
- 后端在没有地图客户端时不做压缩；有客户端时，每个地图版本只在后台线程编码一次并复用给 REST 和全部 WebSocket 客户端。
- 前端解码具有版本顺序保护：网络中较晚完成的旧地图不会覆盖较新的地图。

## 验证与边界

- 已完成 Python 编译检查、前端 TypeScript 检查和生产构建；新增压缩编码与按需缓存回归测试。
- 需要使用支持 `DecompressionStream` 的现代 Chrome；当前部署使用的 Chrome 满足该条件。
- Web 地图仍保持 v0.6.2 设定的最多 1 FPS 刷新。ROS2 SLAM、Nav2、速度看门狗和物理急停安全边界均未改变。
