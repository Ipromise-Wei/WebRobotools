# v0.7.1 版本说明

发布日期：2026-09-28

这是 v0.7.0 工控机本地控制链路的现场问题修复版，处理地图显示精度、地图保存、视频最新帧和自动建图停止。

## 地图显示与保存

- 工控机 `telemetry_relay.py` 的显示地图上限从 65,536 提升至 262,144 栅格（约 `512 × 512`），发布上限从每秒一次提高到每秒两次。原始 `/map` 仍只在工控机本地保留；跨网地图仍为 `BEST_EFFORT + VOLATILE + depth=1`，不会造成可靠重传或旧地图队列。
- 正常配置下 Web 端与中继使用相同的 262,144 栅格上限，不会对已正确中继的地图再次降采样。目标安全校验仍严格在工控机原始地图上进行，显示精度变化不会降低目标点校验。
- 保存地图时，`map_saver_cli` 明确使用 transient-local 地图订阅并将 `save_map_timeout` 设置为 25 秒。命令成功后还会检查 `<名称>.yaml` 和 `<名称>.pgm` 是否同时为非空文件；失败消息会指出等待地图或文件生成失败。

## 最新数据优先的视频流

SSH 是可靠的 TCP 通道，旧帧曾可能在短暂拥塞后被逐帧读出。本版在工控机运行私有的最新帧中继：它持续采集并只保留一个最新 JPEG；Web 后端只有准备好消费时才经 SSH 请求一帧。因而 TCP 中不会连续排入未显示的旧视频。SSH 不再尝试压缩已压缩的 JPEG，并请求低延迟 QoS；HTTP 响应增加禁止 Nginx 缓冲的头。这样视频恢复后优先显示最新图像，而不是回放积压画面。

这不会绕过物理网络容量：若网卡持续饱和，仍应降低相机分辨率或给控制网络使用独立 VLAN/NIC。但地图、视频和控制处理均已采用有界且最新数据优先的策略。

## 可随时停止自动建图

停止建图、切换到手动建图、以及单独停止 Frontier 时，Web 服务器会先在工控机执行：

```bash
ros2 run frontier_exploration_ros2 frontier_exploration_ctl stop
```

随后运行代理回收 Frontier 与其余建图模块进程。控制服务已经退出、暂时不可用或停止命令超时时，进程组回收仍继续执行；停止 API 和浏览器等待上限同步延长，避免“正在停止”被过早报告为失败。

## 升级与现场验证

升级后必须先停止当前建图任务，再重新启动手动或自动建图，新的工控机中继和运行配置才会部署到工控机。建议依次确认：

1. 地图模块中显示的分辨率接近 `512 × 512` 或与原图等比例的更高分辨率；
2. 点击“保存当前地图”后，地图文件列表出现名称，且工控机目录中同时存在 YAML 与 PGM；
3. 打开视频并移动机器人时，视频恢复后显示当前画面而非数秒前的帧；
4. 自动建图运行中点击“停止建图”，确认 Frontier 目标取消、模块状态依次变为已停止。

任何移动测试都必须保持人员监护和物理急停可触达。Web 停止与软件超时不替代硬件急停。
