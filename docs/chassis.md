# 底盘模块

离线开发可使用 `MockChassis`；当前真机配置使用 ROS2 底盘控制器。速度输入范围由 API 模型校验：线速度 `[-1, 1]`，角速度 `[-2, 2]`。

ROS2 模式使用 `MiniV3ChassisController`，Topic 均由 YAML 配置。Web 速度命令发布到 `/webrobot/cmd_vel`，只有工控机侧速度看门狗持续在线时才允许控制。看门狗负责转发到 `/cmd_vel`，并在命令超时后持续发送零速度。

地图工具栏新增“清地图缓存”，地图右上角独立导航卡片提供“设置目标”和“取消导航”。清缓存仅清 Web 后端的最新中继显示地图与路径快照，不影响工控机上的原始 SLAM 地图、地图文件或正在执行的导航；下一次中继发布地图时会重新显示。设定目标时点击地图给定位置，拖动确定机器人最终朝向，确认后经工控机实时通信中继发送给本机 Nav2 `/navigate_to_pose` Action Server。中继会使用原始本地地图再次校验坐标系、范围和空闲栅格。导航期间手动驾驶区显示接管锁定，停止按钮会请求中继取消 Nav2 目标；取消完成前不能切回手动驾驶。Web 停止不替代现场硬件急停。

Web 模块面板不再提供 CAN0 开关，也不会执行 `sudo` 或修改工控机网卡。启动底盘模块前，工控机上的 `can0` 必须已由现场运维配置为 UP、500000 bit/s；底盘运行脚本只读检查该状态，不满足条件则拒绝启动。运行中若网卡掉线或比特率变化，底盘任务会停止。请在工控机上由有权限的人员管理 CAN 接口，Web 端不会替代这一操作。

从旧版本升级时，如果旧版 CAN0 任务还在运行，不要直接用“全部停止”：旧脚本退出时会把 `can0` 置为 down。先确认底盘及其他使用 CAN 的设备已安全停机，再按现场流程处理旧任务。若界面仍收到旧版 CAN0 清单，应重启 Web 后端以加载新配置；新版界面在此期间会隐藏旧按钮并锁定模块操作，避免误改网卡。

导航模块改由工控机上的 `nav2_web_runtime.py` 启动。它基于工控机已安装的 Nav2 Humble 启动文件，将速度平滑器最终输出重映射到 `/webrobot/nav_cmd_vel`，并将 Nav2 恢复动作的速度输入接入同一平滑链路；若安装版本的启动文件不匹配，模块会拒绝启动，不会绕过速度看门狗。`telemetry_relay.py` 同时在工控机本地拥有 `NavigateToPose` Action Client，并把原始 `/map`、完整 `/plan` 转换为可丢弃的显示 Topic。速度看门狗只依据本地 Nav2 Action 状态与新鲜本地 Nav2 速度转发导航速度；本地速度超过 0.5 秒未更新时仍归零。Web 端发布的是请求关联的低频控制租约，10 秒失联后由中继请求取消无人监管的任务，不会因普通视频或地图传输抖动造成走停。不要同时手工启动另一个直接向 `/cmd_vel` 发布速度的 Nav2 实例。运行中继的工控机 ROS2 环境需要 `nav2_msgs`（Ubuntu/ROS2 Humble 通常由 `ros-humble-nav2-msgs` 提供）。
